# 無人実行の認証方式案

#85 の初回運転では、隔離した試験専用プロファイルでHermes標準の認証保存を使う方式を推奨する。
固定版の保存処理で、合成認証ファイルが600、親ディレクトリが700となり、別プロセスから再読込できることを通信遮断コンテナで確認した。
保護境界はOS利用者単位。同じOS利用者の別プロセスも読めるため、アプリ限定の保護が必要な場合はこの方式を採用しない。
正式採用と実OAuthの登録は人間判断を要する。

| 方式 | 確認結果 | 必要な準備 | 更新時の扱い |
|---|---|---|---|
| Hermes標準の隔離プロファイル | 通信遮断Dockerで保存権限と別プロセス読取成功 | 試験専用の永続保存先と利用者権限 | 既存の排他・原子的保存を再利用 |
| Data Protection Keychainのアクセスグループ | 合成項目の作成が -34018 で失敗 | ワーカー用entitlementと、それを許可するprovisioning profile | 同じ権限と署名条件を維持して更新 |
| 従来型Keychainの専用アプリACL | 合成項目の直接読取・LaunchAgent読取成功、別識別子アプリは拒否 | 固定した署名済みワーカーと試験用の新規項目 | 更新後も署名と読取境界を再検証 |

従来型のACL APIはdeprecated。アプリ限定の保護が必要な場合は、Data Protection Keychainの権限を整える案を再評価する。
署名証明書が利用可能なだけではData Protection Keychainの前提は満たせない。
この比較は合成試験に基づく。画面ロック中のLaunchAgent実行は未検証。

## 初回試行の境界

- 利用者がログイン中のユーザーLaunchAgentを対象とする。ログアウト中とMacの再起動後にログインする前は起動対象外とする。
- 標準プロファイル方式では、ホストの試験専用領域の所有者と700/600権限を確認する。通常のHermes本番プロファイルと分離し、リポジトリ外に置く。隔離ワーカーに渡す認証は一時領域だけに展開する。
- 合成試験で画面ロック中の読取、欠落、拒否、期限不足を確認してから、実OAuthの扱いを判断する。ワーカーは許可画面を出さず、認証不能を状態として返す。
- 実OAuthを使う場合は、承認された試験専用の保存先を使い、既存の試験項目と本番認証を保全する。秘密の出力は専用プロセスから隔離ワーカーへのパイプに限定する。標準出力ログ・引数・環境変数へ置かない。
- OAuth更新を行う場合は所有者を1つに固定し、更新結果の保存を確認するまで次の実行を許可しない。更新応答の途絶や保存失敗では停止し、同じ更新トークンを自動で再使用しない。
- 認証更新の通信許可と回数は推論とは別に確認する。更新未承認または期限不足なら AUTH_FAILED で停止する。
- 緊急停止は新規受付と実行中のワーカーを停止させ、一時認証を破棄する。永続保存先の認証を削除する操作は、再開と区別して監督者が判断する。

## 検収手順

1. 選定方式の試験専用領域に合成認証を保存する。
2. 一時LaunchAgentを起動し、ロック前とロック中の読取を確認する。標準プロファイル方式では利用者権限、アプリ限定方式では別アプリの拒否を確認する。
3. 合成の有効期限切れと欠落を模擬し、実行前に停止することを確認する。
4. 一時登録と合成項目を削除し、消失を照合する。
5. 実OAuthの試験専用領域への登録、単発の実推論、更新許可を個別に判断する。

## 実機確認の結果（2026-11-07 JST）

保存済み試験用OAuthを読み込む一時LaunchAgentで、固定版Hermesから公開合成文をGPT-6 Lunaへ1回送信した。
HTTP 200、期待した固定応答、推論1回、再送0回、ツール0を照合した。
一時LaunchAgentと実行コンテナの消失も確認した。
認証更新はこの試験の送信ガードで遮断する。

先行試行では、ローカル期限が有効でもサーバー側のトークン無効化で401となった。
承認された更新1回も401となり、本人の再認証を経て試験専用プロファイルへ保存した後、上記の試行が成功した。
認証失効をローカル期限だけで判断せず、拒否時は停止して人間に確認する。

この実機試行は一時の検証ハーネスで行った。
通常入口は scripts/run_public_hermes.py に追加した。
既定では選定と送信計画の出力までを行う。実行には監督者の承認ファイルと --execute が必要。
画面ロック中の実行確認は、後述の通常入口の検収で完了した。

## 通常入口と送信承認

`python3 -I -B scripts/run_public_hermes.py --run <完了点検> --evidence-dir <証跡領域>` は、送信する公開入力のハッシュ、対象イベント、snapshot、イメージID、モデルと上限を計画として返す。
監督者はPlusの利用枠と追加クレジット設定を確認し、その計画の全項目に1時間以内のUnix秒 `expires_at` を加え、本人だけが読み書きできる承認ファイルとして保存する。
ファイルは承認の監査記録であり、ローカル利用者が作成したこと自体を利用者の同意の証明とはみなさない。
`--execute --approval <承認ファイル>` を追加すると、対象と期限を照合してから最大1回だけ起動する。

実行先は検証済みの固定HermesイメージIDで固定する。
イメージがローカルにない場合は停止し、変更可能なタグを自動取得しない。
試験専用認証だけをパイプでコンテナの一時領域へ渡し、Dockerログは無効とする。
固定版のHTTP輸送層とPythonのソケット監査で、許可されたリクエスト以外の外向き通信を拒否する。
同じプロファイル内の送信ゲートをgatewayとCLIで共有し、認証更新と再送を拒否する。

`--stop` と `--resume` は通常入口の実行領域に適用する。
停止時は記録のワーカー種別とコンテナ設定を照合し、対象コンテナIDだけを停止する。
この段階の応答はHOLDまたはNO_CHANGEに限定し、修正候補の接続は #86 で扱う。

## 通常入口のオフライン検証

固定Hermesイメージで新しいワーカーを通信遮断して起動し、標準形式の合成認証、模擬応答、送信ゲート1回、ツール0、コンテナ削除を確認した。
最初の試験入力は標準認証の識別項目が不足していたため初期化で停止し、試験入力を修正して再検証した。実認証と外部通信は使っていない。
承認不一致・期限切れ・差し替え、認証ファイルの欠落・権限不正・期限切れ、認証拒否、重複受付、停止制御と隔離後始末不明時の再開拒否はオフラインテストで確認する。
制御テストは `python3 -I -B -m unittest discover -s tests -p 'test_public_hermes.py'` と `test_mock_improvement.py` を対象にした同コマンドで実行する。
標準CI入口はSecurity側の承認済み固定資産のため、このPRでは変更しない。標準verifyの設定テスト30件と、別途実行する制御テスト24件を区別して記録する。
通常入口の実行関数を通した実通信と画面ロック中の確認は、次の検収結果を参照する。先行の一時ハーネスの実通信成功とは分けて扱う。

## 通常入口の実行関数の実機検収（2026-11-07 JST）

本人が今回の1回の送信を承認した後、一時LaunchAgentから `run_public_hermes.execute` を実行した。
入力は996 bytesの公開合成文で、実CI障害と混同しない試験ラベルを付けた。
既存の試験専用プロファイルを再利用し、新しいデバイス認証・認証更新は行っていない。
GPT-6 LunaのHTTP 200と、検証済みのHOLD応答を確認した。推論1回、再送0、ツール0、期限30秒、申告済みのPlus利用枠・追加クレジットOFF・追加費用0円の条件で実施した。
サーバー側の利用枠や請求額を照会した結果ではない。

起動前と終了後のログインセッションと画面ロックを確認し、実行中の44回の観測もすべてロック中だった。
LaunchAgentは1回で終了コード0。一時登録を解除し、試験コンテナの消失と隔離pendingレシートの除去を照合した。
承認ファイルと耐久的な試行記録は保全し、同じ試験を自動再実行しない。
